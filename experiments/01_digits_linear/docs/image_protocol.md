# 图像协议 v1

物理层沿用 115200 baud、8N1、无流控。每次只允许一幅图在途：电脑发送完整请求，
收到完整响应并核对序号与 CRC 后，才发送下一幅图。所有字段都是原始二进制字节，
不是十六进制字符文本，也不是 PNG/JPEG 文件内容。

## 请求：69 字节

| 字节偏移 | 内容 |
|---|---|
| 0～1 | 固定帧头 A5 5A |
| 2 | 序号 0～255，可循环使用 |
| 3 | 像素数，固定 64（十六进制 40） |
| 4～67 | 8×8 图像按行展开；每个像素一个 uint8，数值只能是 0～16 |
| 68 | 对偏移 2～67 计算的 CRC-8 |

训练使用过 x/16，导出时已将 /16 合并进权重。传送时直接发送原始 0～16 像素，不能再除以 16。

## 成功响应：46 字节

| 字节偏移 | 内容 |
|---|---|
| 0～1 | 固定帧头 5A A5 |
| 2 | 回显请求序号 |
| 3 | 状态，成功为 00 |
| 4 | 预测类别，0～9 |
| 5～44 | 类别 0～9 的十个 signed int32 分数，每个按小端字节序传输 |
| 45 | 对偏移 2～44 计算的 CRC-8 |

这些是整数分数，不是概率。负数采用二进制补码。
Python 以 `struct.unpack('<10i', ...)` 还原，并与相同整数模型的全部分数逐项比较。
比较完整分数比只比较预测类别更容易发现错位、符号和权重问题。

## CRC 与错误处理

CRC-8/SMBUS 参数：多项式 0x07、初值 0、非反射、无最终异或。
标准检查串 ASCII `123456789` 的结果为 F4。帧头不参与 CRC。
该 CRC 用于检错，不用于认证，也不能保证检测所有组合错误。

- 帧长不是 64、像素超出 0～16 或 CRC 不正确：不启动推理，不发响应，LED2 置亮。
- 接收帧期间连续 50 ms 没有收到下一个字节：丢弃不完整帧，重新寻找帧头，LED2 置亮。
- UART 停止位错误：丢弃当前接收帧，LED2 置亮。
- 推理或响应发送期间收到新字节：丢弃新字节，LED2 置亮；发送方应遵守一次一帧。
- 解析器重回帧头扫描后，完整合法的新请求可恢复工作；LED2 保留错误历史，S4 清除。
- 电脑等不到响应超过 2 秒即报错，不盲目连续重发。先留存错误，等待至少 50 ms 静默后再发完整帧，必要时用 S4 复位。

不完整帧可能已覆盖部分像素 RAM，但只有通过整帧校验才会启动推理；下一幅合法图必须写满 64 个像素。
本协议固定一个模型和一个图像尺寸，不包含自动版本协商、运行时换权重或摄像头预处理。

## 三层验证

1. 分类核心：454 张图，全部 4540 个整数分数核对。
2. 字节协议层：454 张图及恢复测试，响应含序号、类别、全部分数和 CRC；施加发送端背压。
3. UART 集成层：10 张图经过实际串行位波形收发，核对 460 字节响应。

电脑端 `image_protocol.py` 与 FPGA 协议状态机分别实现 CRC；`prepare_protocol_vectors.py`
检查标准 CRC 值、非法输入和错误响应，然后从整数测试向量产生帧参考数据。
