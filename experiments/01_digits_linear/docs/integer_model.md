# 软件与硬件的数值约定

## 从图像到分数

8×8 图像按行展开为 64 个像素 `x[i]`，范围是 0～16，用 uint8 存储。
训练时输入 `x/16`，得到浮点权重 `W[c,i]` 和偏置 `b[c]`。

```text
浮点分数：z[c] = Σ (x[i]/16) × W[c,i] + b[c]
有效权重：W_eff = W / 16
共同尺度：s = max(abs(W_eff)) / 127
整数权重：Wq = clip(round(W_eff/s), -127, 127)
整数偏置：bq = round(b/s)
整数分数：q[c] = Σ x[i] × Wq[c,i] + bq[c]
输出类别：argmax(q[0], ..., q[9])
```

近似关系是 `z[c] ≈ s × q[c]`。所有类别共用同一个正尺度，因此可以直接比较整数分数。
偏置必须使用与乘加结果一致的尺度；不能独立把偏置也压到 int8。
取最大分数即可分类，推理硬件不必计算 softmax。
分数并非概率；本实验也不输出置信度。

NumPy 的 `rint` 使用 ties-to-even 舍入。舍入在电脑导出时完成，RTL 不再做浮点运算。
这是 int8 权重、uint8 输入和 int32 偏置/累加的混合整数实现，不是“全部 8 位”。

## 位宽和溢出

- 输入：uint8，但合法值限制为 0～16；RTL 扩成正的 signed 9 位再乘。
- 权重：signed int8，导出范围 -127～127。
- 乘积：signed 17 位，符号扩展到 32 位。
- 偏置和累加器：signed 32 位。
- 每类绝对值保守上界：`abs(bq[c]) + 16 × sum(abs(Wq[c,:]))`。
- 导出脚本检查所有类别的上界小于 `2**31`；更换模型后要重新验证。
- 软件参考先以 int64 累加，确认上述范围后才与 RTL 的 int32 对比。

本实验没有饱和算术；在输入约定内依靠上界保证不溢出。
若换成 0～255 的图像，必须重新设计预处理和上界，不能直接发送原始 JPEG/PNG 字节。

## 文件布局

`weights.mem`：640 行，每行两位十六进制，先存类别 0 的 64 个权重，再存类别 1。
负数用二进制补码，例如 `ff` 表示 -1。`biases.mem`：10 行，每行八位十六进制。
`images.mem`：每张图 64 个逐行排列的像素。`scores.mem`：每图 10 个 int32 参考分数。
`predictions.mem`：每图一个类别。

仿真和综合都从 `build/model/` 读取这些文件；脚本负责设置工作目录。
Vivado 综合会使用 `$readmemh` 初始化模型存储，后续生成 bitstream 时模型随电路配置写入。
本实验换模型需要重新导出并重新构建；运行时动态更新权重属于后续扩展。

## 核心接口约定

1. `rst` 是同步高有效复位；复位时不清空像素 RAM，下一次推理前必须写满一幅图。
2. `busy=0` 时可以逐地址写入 64 个像素；`pixel_we` 与 `start` 不同时置高。
3. 写入完成后 `start=1` 一个时钟；在忙期间写像素和启动信号均被忽略。
4. 每个像素用 FETCH 和 MAC 两个状态完成取数及乘加，先求完一类，再算下一类。
5. `score_valid` 指示一个类别的分数有效；共输出 10 次。
6. `done=1` 一个时钟时，`prediction` 有效且 `busy=0`。
7. 多类分数相同时，选择编号最小的一类，与 NumPy `argmax` 一致。

核心没有检查“是否已写满 64 个像素”，板级控制模块必须履行该协议。
仿真核对的是完整协议内的行为；串口错误恢复等需要在板级模块加入后单独验证。
